## What there is to integrate with

**Nothing, as of 2026-08-06.** Axena Health operates no developer portal, no public API reference,
no OpenAPI or other machine-readable contract, no SDKs, no CLI, no webhooks, no sandbox, no GitHub
organization and no published packages on npm, PyPI, Maven Central, NuGet, pkg.go.dev, RubyGems,
Packagist or crates.io. Leva is prescribed, dispensed and used as a regulated end-user product; the
software is not offered as a platform.

Two machine-readable surfaces do exist, and both are WordPress platform plumbing rather than product
APIs. They are recorded here because they are real and anonymously discoverable, not because they
constitute a developer program.

## Machine-readable surfaces found

- [WordPress REST API — levacares.com](https://levacares.com/wp-json/): 200. The default WordPress
  REST discovery root for the Leva Pelvic Health System site, 472 routes across 20 namespaces
  (wp/v2, wp-abilities/v1, mcp, plus plugin namespaces). Content routes only — posts, pages, media,
  taxonomies. No clinical or device data.
- [WordPress REST API — axenahealth.com](https://axenahealth.com/wp-json/): 200. The same, for the
  corporate site: 324 routes, 20 namespaces, no `mcp` namespace.
- [MCP Adapter — levacares.com](https://levacares.com/wp-json/mcp/mcp-oauth-server): 401. A live
  WordPress MCP Adapter endpoint. `tools/list` returns `mcp_unauthorized`; the tool set cannot be
  enumerated without an OAuth bearer token in the `mcp` scope.
- [MCP Adapter (default server)](https://levacares.com/wp-json/mcp/mcp-adapter-default-server): 401.
- [OAuth Authorization Server Metadata](https://levacares.com/.well-known/oauth-authorization-server):
  200, RFC 8414. Authorization code + refresh_token, PKCE S256 required, public clients only, one
  scope: `mcp`.
- [OAuth Protected Resource Metadata](https://levacares.com/.well-known/oauth-protected-resource):
  200, RFC 9728. Binds the `mcp` scope to the MCP adapter endpoint.
